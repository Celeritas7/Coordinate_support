Decisions in one place

  • Use as stations goes. Check route reads the ticked rows directly. This is the main cut, and it is why the main path fits in 5 steps (7 on the frame with start and end picked in 3D).
  • An empty Start or End is filled by the next 3D click. The pick panel confirms it and offers Undo. Picking start and end then costs 1 click each, not 2.
  • The task list goes from a 124 px column to a row of tabs under the module switch. The cards get the full sidebar width (≈ 466 px).
  • The assembly line moves above the module switch because it is shared by every module. It reads 3 clamps for Ø12 once Hose Ø is known.
  • Tables go to the dock: Clearance, Clamps to add (Suggest extra clamps) and CSYS made here. The sidebar keeps one verdict line and the Next buttons.
  • One Advanced toggle above the strip. When it is on, each card shows its own settings block. When it is off, the current values are shown in one mono line beside the toggle, so R and gap stay visible.
  • Amber text fails contrast in light (2.7 : 1). Amber stays for fills, borders and markers. Amber words use one new token, --warn-ink #8F5A0A (light only; dark keeps --warn).

Acceptance checklist · Phase 5

  • ui-walk.js A ≤ 7 steps (target 5) and F ≤ 7 steps to a downloaded .pts, with no click on a summary or [aria-expanded] fold on either path.
  • The strip shows exactly three cards with headings “1 Load”, “2 Stations”, “3 Route”. The current card has the filled number; there is exactly one current card.
  • No Use as stations button exists. Check route with fewer than 2 ticked rows is disabled and reads “Tick at least 2 stations.”
  • With Start empty, a click on a part or CSYS sets Start. With Start set and End empty, it sets End. Each one shows the panel message with Undo. A drag (rotate) never sets anything.
  • When Advanced is off, the mono summary line shows the current R, margin, gap and fit. Switching Advanced on and off keeps every value. The state is saved like the theme.
  • At 1366 × 768 the sidebar never scrolls sideways, no card text is clipped, and the view tools do not overlap the readout.
  • Below 900 px of height, done cards collapse to their summary line. The summary is a button with aria-expanded.
  • Clearance, Clamps to add and CSYS are dock tabs. The tab labels carry a count when it is above 0.
  • Each Pipe task shows its one-line empty state (table above) until it has input.
  • Light and dark screenshots of A and F at both sizes are saved as handoff/shots/P5-*.png.

Accessibility keyboard order, focus, contrast

Keyboard order (Tab)

  1. Top bar: Open… · Examples · More · Dark
  2. Assembly line: Change… · Remove
  3. Module switch (one tab stop; ←/→ move between modules), then the task tabs (one tab stop; ←/→)
  4. Advanced toggle
  5. Card 1: summary button (when collapsed) · Hose Ø · Keep clear fold
  6. Card 2: Start · End · Auto order · Untick all · Only picked · then per row grip → tick → remove · Other holes · Hold bore direction · Points as text
  7. Card 3: Push tick · Check route · Next buttons · Alternatives section · Tools links
  8. Runs in 3D
  9. View tools (left to right) → 3D canvas → pick panel (when open) → dock tabs → dock body

Drag handles (station grip)

  • A real <button>, 24 × 28 px, with aria-label="Move S2 CS16, position 2 of 5" and aria-describedby pointing at a hidden hint, “Arrow keys move it”.
  • ↑ / ↓ move the row by one, and focus stays on the same grip. Home / End move it to the top or bottom. Every move renumbers S1…Sn and is announced through a polite live region: S2 moved to position 3 of 5.
  • Focus ring: outline:2px solid var(--focus); outline-offset:0, and the glyph turns --ink. A mouse drag also shows the existing .over top rule in --focus.
  • When a 3D pick opens the pick panel, focus goes to its first action. Esc closes the panel and returns focus to the canvas. When an armed click sets Start or End, focus goes to Undo.
  • Segmented controls (Keep clear yes/no, the side choice, CSYS none/holes/all, Colour) use role="radiogroup", with ←/→ to change and one tab stop each.

Phase 3 · Next buttons and pre-check messages

The six result lines (card 3 unless noted)

Rules

  • Place: directly under the verdict line, in the card that produced it. Never inside a fold.
  • At most 3 buttons. The first is primary (.btn.pri, ink fill), the rest are outlined. Replace .next button:first-of-type{font-weight:600}.
  • Order: fix the worst problem → look at other options → deliver.
  • Verdict keyword: Clash: / Too tight: in --bad; Close: and the pre-checks in --warn-ink with an amber marker; Clear: in --ok. Facts after it in --ink, details in --muted.
  • Error = the result breaks a rule (into a part, below min R). Warning = it passes but inside the margin, or a pre-check doubts the input. Warnings never disable Check.
  • After Alternatives: yes. Use this / Use anyway replaces the verdict for that alternative and shows Next again (Download .pts · Suggest extra clamps).
  • Labels are 4 words at most, and none wrap at 466 px.

Acceptance checklist · Phase 3

  • Each of the six cases shows the exact line and buttons above (tests/ui-walk.js reads the text).
  • Exactly one .btn.pri per Next row.
  • The stations-too-close pair is marked amber in the station list with its distance.
  • A mount row reads “Mount of S2 (its clip is bolted to it) · not kept clear”.

Phase 4b · pick the side

The same choice in two places, kept in sync

Decisions

  • Where: both. The pick panel is the main place, because you see the part. The Keep clear row has a compact select for parts that are hard to click. It is one state, saved per file.
  • Words: any · over · under · left · right. Keep “over / under” (not Above / Below): it reads with “passes”. When the leg runs along the up axis, the row shows axis words instead: any · +X · −X · +Y · −Y.
  • “Left” on a route that turns back: it is judged on the leg that passes the part, looking from the earlier station to the next one. So the label always names the leg: Route passes it · looking S3 → S4 · up +Z. A part met by two legs shows the first one, with a muted line “also met S5 → S6; same side kept”.
  • Forced: an amber forced side tag on the card, the failing numbers in red, and one amber note over the cards: Over 980709 cannot hold R 65; best that side is R 58. With any side: 2 clean routes, both under it. [Clear the side choice]. Never red for the choice itself.
  • Up: a select in the Alternatives header and in card 1 Advanced: Up +Z ▾, with the options +Z −Z +Y −Y +X −X. A guessed value says so: +Z (guessed). Its label is “Up (for over / under)”.
  • Chosen sides show as chips above the cards (over 980709 ×). × clears that part’s choice.

Acceptance checklist · Phase 4b

  • Setting “over” in the pick panel updates the Keep clear row select at once, and the reverse.
  • The side row label names the leg (Sa → Sb) and the up axis.
  • On a leg along the up axis, the seg shows axis words.
  • A forced result shows the tag and the amber note, and nothing red except the failing numbers.
  • The walk-through gains at most 1 step for a side choice.

Q1–Q7 items

Pick panel · button order and grouping

  • Groups, in order: Route · Keep clear of it · Route passes it · Creo · Library. Group labels are 11.5 px muted.
  • Route: the primary button is whichever is still needed, in the order Use as start → Use as end → Add as station. The others follow in that same order. (This replaces “station first” from Q1–Q7 §1, because start and end are now armed.)
  • Header: name (mono 600) · kind · ×. Parent on its own muted line. Facts: size · role · where clicked.
  • On a +n suggestion dot: Make CSYS (primary) · Add as station · Drop this one.

CSYS made here · rows (dock tab CSYS)

  • Two lines, never three. Line 1: name (edit in place) · Show · Flip Z · X +90° · ×. Line 2: at origin · Z select · X word.
  • Z is a select, +X −X +Y −Y +Z −Z typed…. Choosing typed… shows the 3-number field in place of the select. Quick buttons would take 6 buttons per row; the select takes one control.
  • The Z select is width:auto; the separators are gaps, not “·”.

Suggest extra clamps · result rows (dock tab Clamps to add)

  • Four facts in four columns: where (+n chip, along mm) · why · mounts on · like. Make CSYS is a link in the last cell.
  • “Needs a bracket” is an amber outlined tag in the mounts-on cell, with the muted “no part within 60 mm” under it. Never red. The tab label counts it: Clamps to add (3 · 1 needs a bracket).
  • Group rows per span (S3 → S4 · 669 mm · 2 clamps). Clicking a row selects its dot in 3D and opens the pick panel.
  • Sidebar line: 3 clamps to add on Generated R65 ×1.5; 1 needs a bracket. Next: Make CSYS for all · Add all as stations.
